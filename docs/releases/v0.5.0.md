# CommyPanel 0.5.0

This release is about backups you can rely on: restoring a database dump from the panel, copying backups to storage off the server, backing up app volumes, and a warning before the disk fills up. It also contains the fixes from a security review of the agent's database and network actions, so please read **Before you upgrade**.

CommyPanel is still pre-1.0.

## What's new

### Backups

- **Restore a database dump from the panel.** Press **Restore** next to a dump on a database server's page, choose a name, and it is loaded into a **new** database, so nothing that exists is overwritten. The new database has its own user and password and shows "Restoring" until done (or "Restore failed" with the reason). Link it to the app, deploy again, and delete the old database when you are sure.
- **Copy backups to another place (S3).** Under **Settings > Backups**, every new panel backup, database dump and volume archive can be copied to any S3-compatible storage: Hetzner Object Storage, Cloudflare R2, Backblaze B2, Wasabi, MinIO, Amazon S3. **Test the connection** checks the settings. The newest 14 copies of each backup are kept there (changeable); files that are not CommyPanel backups are never touched. The secret key is stored encrypted and never shown again.
- **Back up app volumes.** A **Back up** button per volume on the app's **Volumes** tab makes a compressed archive in the background (the newest 3 of each are kept). Nothing is backed up by itself, because volumes can be large. Downloads and deletes need your password and are audited.
- Each database server's page now explains how restoring works, and the Backups pages explain the copy.

### Server health

- **A warning when the disk is nearly full**, on every page, from 85% used (an error from 95%; `DISK_WARN_PERCENT` and `DISK_CRITICAL_PERCENT`). The **Server** page has a new **Disk** card with a usage bar and the five biggest app volumes.

### Apps and links

- **The name other apps call an app by moves with the traffic.** Before, the old and the new release both answered to a provider app's link name during a deployment. The new release now takes the name only once it is healthy and has traffic, and the old one gives it up right after.

### Installing

- **CI installs each release** on Debian 13, Ubuntu 24.04 and Ubuntu 26.04 before it is published, and the tests also run on PHP 8.3. This is why 0.4.1 and 0.4.2 happened; it is meant to stop that kind of problem reaching you.

## Before you upgrade

- **Back up `/var/lib/commypanel`** as with any upgrade, and upgrade with `sudo commypanel upgrade`. The migration adds three columns to `managed_databases`.
- **The agent has a new private folder, `/var/lib/commypanel-agent`**, outside the data directory, created by systemd. It now holds the agent's scratch files, the record of the dumps it made, **the TLS private keys, the ACME account key and the ACME challenge files**, which used to sit under `/var/lib/commypanel`. Only root can change anything in it. The upgrade rewrites the agent's service file for it. Certificates are not moved: apps get theirs again from Let's Encrypt, so a server that already has certificates should expect them to be requested again after upgrading.
- **No new permissions.** Restoring a dump needs `databases.manage`, volume backups need `apps.volumes`, and the S3 copy needs `backups.manage`.
- **The panel contacts your S3 storage** once you switch the copy on, and nothing before. Updates remain the only other call it makes by itself.

## Security notes

- **The agent's own files are out of the panel's reach.** A compromised panel could swap a temporary dump file for a link to a root-only file (the agent would then send its contents back), forge a record of a dump, or replace the certificate folder so that new private keys were written where it can read them. The scratch files, the dump records, the TLS keys, the ACME account key and the ACME challenge files now live in a folder only root can change.
- **Extra networks are link networks only**, and a link network is never a container's own: a container can no longer join another app's or a database server's network, or put a name on it that answers in their place.
- **A command that is still running when its output ends is a failure**, not an exit code of 0, so a dump cut off by the time limit is no longer kept as a good backup.
- **Database tools run only in database servers**: managed containers named `db-*` started from an official database image. An app and a database server can only mount their own kind of folder.
- **The build context is read through a root** that cannot be left, and each file is checked again when it is opened.
- **Big jobs are limited**: at most two dumps, restores or volume archives run at once, and none starts with less than 2 GB of free disk, so repeated requests cannot fill the disk. The data of a database server is never deleted when Docker cannot be asked whether something still uses it. A volume's source path can no longer carry extra bind options.
- A restore runs as the database's own user for PostgreSQL. The S3 address must be https and not this server or a link-local address, redirects are never followed, and the secret key is encrypted.

## Known limitations

- **Backups are not read back from the S3 storage** by the panel: download the file there and use the commands in the docs. Single uploads are limited to 5 GB.
- **A volume archive is put back by hand** (stop the app, `tar -xzpf` as root), and a database dump is restored into a new database only; there is no "replace" mode yet.
- The S3 client was tested against AWS's published test vectors and a real S3-compatible server, not yet against every provider; please report what you find, with the provider's name.
- Not in this release: API tokens, one-click GitHub connection, wildcard certificates.

## Requirements

Unchanged: Ubuntu 24.04 or 26.04, or Debian 13 or newer, with systemd; `amd64` or `arm64`; root access; at least 1 GB of RAM.

```bash
# Install
curl -fsSL https://github.com/emrecanful/commypanel/releases/latest/download/install.sh | sudo bash

# Upgrade
sudo commypanel upgrade
```
