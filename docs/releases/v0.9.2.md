# CommyPanel 0.9.2

A small release that fixes **redeploying an Elasticsearch app** (and Redis and Garage), and lets you choose an app's **memory on the create page**.

## What was wrong

A normal deployment starts the new version next to the old one and switches when it answers. Elasticsearch, Redis and Garage must never run twice on the same data: the second Elasticsearch node exits a few seconds after it starts (it cannot lock the data folder), so a deploy could not succeed, and changing the memory limit and deploying again left the app without a working new version.

## What's new

- **A deploy mode "Stop the old version first".** The new **Deploy mode** setting on an app's Settings tab (and in the new-app wizard) can be **Zero downtime** (what apps have always done) or **Stop the old version first**. In the second mode the image is built and the release command runs while the old version still serves, then the old version stops, the new one starts and must pass its health check. If it does not, the new container is removed and **the old version is started again**, also when the worker dies in the middle. Rollbacks and Apply changes use the same mode, and each deployment's page shows the mode it used.
- **Ready-made Elasticsearch, Redis and Garage apps use it from the start**, and the upgrade moves the ones you already have. The "stop the app first, then deploy" advice for Redis and Garage is gone.
- **Memory on the create page.** Choosing a ready-made app shows a **Memory limit (MB)** field, filled with what the app is made for (for example 2048 for Elasticsearch). Elasticsearch, Kibana and n8n refuse a value below what they need to run (1536, 1024 and 2048 MB), because the system would kill them for lack of memory. You can still change the limit later on the app's Settings tab.

## Before you upgrade

- **The upgrade adds columns** (`deploy_strategy` on apps and deployments) and moves your existing **Elasticsearch, Redis and Garage** apps to the new mode. Run `sudo commypanel upgrade`.
- **If an Elasticsearch app is stuck after a memory change, deploy it again once you have upgraded.** Its data is kept (it lives in a volume).
- **A stop-first app has a short outage on every deploy**, apply and rollback: nginx answers 502 until the new version answers. Gradual rollouts and the watch do not apply to such an app.
- No new permissions and no new ports.

## Known limitations

- A stop-first deployment has not yet been run on a real server with all three apps.
- Everything else in 0.9.1 is unchanged.

## Requirements

Unchanged: Ubuntu 24.04 or 26.04, or Debian 13 or newer, with systemd; `amd64` or `arm64`; root access; at least 1 GB of RAM (2 GB more for Elasticsearch).

```bash
# Install
curl -fsSL https://github.com/commypanel/panel/releases/latest/download/install.sh | sudo bash

# Upgrade
sudo commypanel upgrade
```
