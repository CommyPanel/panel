# CommyPanel 0.11.0

Wildcard domains and certificates, server metrics for Prometheus and Grafana, and four more ready-made apps.

## What's new

- **Wildcard domains and certificates.** Add `*.example.com` to an app and it answers to every name one level below the domain (the bare domain is added on its own; a wildcard takes no `www` redirect). A wildcard name is proven through DNS instead of HTTP. Two ways:
    - **Cloudflare, automatic.** Under Domains > HTTPS > Wildcard certificates paste a Cloudflare API token (from the template _Edit zone DNS_, limited to your zones) and one of your domains. The token is tested, stored encrypted and never shown again; the host agent adds the `_acme-challenge` TXT record itself and removes it, and renewals need nothing from you. Saving and removing the token ask for your password and are audited as high-risk.
    - **By hand, any DNS provider.** The app's Domains tab shows the TXT record to create (with copy buttons) and finishes the certificate as soon as it sees it. **Every renewal asks for a new record** (about every 60 days, with an alert if you use notifications); the certificate in use keeps working meanwhile. **Get new records** starts the order over.

    A wildcard behind Cloudflare's proxy is accepted. Plain names on the same app are still proven over HTTP, all on one certificate. The guide is in the documentation under _Domains and HTTPS_.

- **Metrics for Prometheus and Grafana.** The panel now publishes how busy the server and its containers are at `/api/metrics`, in the format a Prometheus reads: CPU, memory, disk and network of the server and of every container, whether each app and database server is up, and when each app's HTTPS certificate ends. Make a token with the new **Read server metrics** ability (`metrics:read`, needs the **View the server** permission) under Settings > API tokens, and point a Prometheus, on this server or any other, at it. A token limited to some apps sees only those apps. Only numbers and names are published: no variables, logs, addresses or secrets. The panel and the host agent keep working the same way, and nothing new runs on your server. The guide, with a ready scrape configuration, is in the documentation under _Metrics for Prometheus and Grafana_.
- **Four more ready-made apps** (Apps > New app > A ready-made app):
    - **Vaultwarden**, a password manager that works with the Bitwarden apps and browser extensions.
    - **Forgejo**, a small Git host with issues and pull requests (HTTPS only; no SSH port is published).
    - **Umami**, privacy-friendly web analytics. It keeps its data in one of your **PostgreSQL** databases: you choose the database when you install it and CommyPanel links it. Umami ships with the admin password `umami`; CommyPanel replaces it with a generated one on the first start and never touches a password you have set since.
    - **ntfy**, a push notification server. Access is "deny all" by default and an `admin` user with a generated password is made for you; linked apps get `<PREFIX>_USER` and `<PREFIX>_PASSWORD`.

    Vaultwarden, Forgejo and ntfy keep their data in files in a volume, so a deploy stops the old version first (see _Redis, Garage and the apps that keep their data in files_ in the documentation). Vaultwarden and Forgejo have no generated password: make your own account right after the app runs, then switch sign-ups off with the variable named in the app's warning.

## Before you upgrade

- One new column (`certificates.dns_pending`, added by the upgrade), no new permissions and no new ports. Run `sudo commypanel upgrade`, which also updates the host agent.
- The host agent now contacts `api.cloudflare.com`, and only while a Cloudflare token is connected and a wildcard certificate is being made or the token is being tested. Nothing changes for installs that do not connect one.
- New audit entries: `dns.cloudflare_saved` (high-risk), `dns.cloudflare_removed`, `tls.dns_needed` and `tls.dns_refreshed`.
- The new ability is `metrics:read`. The API's own contract (`/api/v1`) is unchanged, but its list of token abilities now has one more entry, so an older client library that checks that list strictly may not know `metrics:read` if you use one token for both a Prometheus and the library. Use separate tokens.
- Installing Umami needs the permission to link apps to databases, and the link is recorded in the audit log like any other.

## Known limitations

- Only Cloudflare is connected automatically. Every other DNS provider uses the manual way, where each renewal needs a new TXT record from you.
- A wildcard certificate covers names one level below the domain only (`*.example.com` is not valid for `a.b.example.com` or for `example.com`).
- Metrics are the readings the Usage tab shows: CPU and network are rates over the last few seconds, not counters, and database internals (queries per second, connections) are not included.
- Forgejo works over HTTPS only. Git over SSH needs a published port, which CommyPanel does not offer for apps.
- Vaultwarden's vault in the browser needs HTTPS, so give the app a domain and wait for its certificate.
- Everything in 0.10.1 is unchanged.

## Requirements

Unchanged: Ubuntu 24.04 or 26.04, or Debian 13 or newer, with systemd; `amd64` or `arm64`; root access; at least 1 GB of RAM.

```bash
# Install
curl -fsSL https://github.com/commypanel/panel/releases/latest/download/install.sh | sudo bash

# Upgrade
sudo commypanel upgrade
```
