# CommyPanel 0.11.0

Laravel apps, wildcard domains and certificates, server metrics for Prometheus and Grafana, and four more ready-made apps.

## What's new

- **Laravel apps, with their own steps.** A repository whose `composer.json` requires `laravel/framework` (with an `artisan` file) is recognised, or you pick Laravel when you create the app. After the access check CommyPanel looks at your code (it reads files, it never runs them) and the wizard continues with **Settings** (PHP 8.2 to 8.5, npm, pnpm or yarn for your assets), **Database**, **Services**, **Volumes**, **Domain** and a **Review**.
- **A database step.** Use an existing database on one of your servers, have a new one made on an existing server, or make a **database server just for the app** whose user can create and drop databases (full rights on that server), for multi-database and tenancy packages. The connection arrives as Laravel's own `DB_*` variables (`DB_CONNECTION`, `DB_HOST`, `DB_DATABASE`, and so on) and follows a password change. Deleting the app keeps a dedicated server and its data as an ordinary server. Every database server's page has a **Permissions** card that shows what each user may do, and lets you change it: on MySQL and MariaDB tick or untick what a user may do on its database (or use the presets Full access, Read and write data and Read only), and change the server-wide rights of a dedicated server's administrator user. This needs `databases.manage` and your password and is audited.
- **Redis.** The Services step can make a Redis just for the app (a ready-made Redis app, linked and started for you), use one you already run, or none. The link gives `REDIS_URL`, `REDIS_HOST`, `REDIS_PORT` and `REDIS_PASSWORD`, and the starting `.env` uses Redis for cache, sessions and queues when it is there.
- **Services: several containers per release.** The scheduler (`php artisan schedule:work`) runs by default; a queue worker, Horizon, Pulse and Inertia SSR are offered when your code uses them, switched off until you switch them on, each with a command you can change, and you can add your own. Workers may overlap the old release for a moment; the scheduler and the other singletons stop the old copy first so nothing runs twice. Rollbacks restore every service. The Logs, Terminal and Usage tabs have a selector for the container, and there is a **Services** entry under Configuration.
- **A release script.** A multi-line script runs before each release goes live, in the new image with your variables, volumes and database (default `php artisan migrate --force`). A failing line stops the release and the old one keeps serving. It is shown on the Review step and on a **Deployment script** page under Configuration. That page and a script field on the Settings step are there for Node.js, Python, .NET and Dockerfile apps too (a single release command still becomes the first line when you save).
- **The `.env` editor.** A Laravel app's Environment tab shows the variables as one `.env` text, comments and order kept. The text is loaded only after you confirm your password, the read is audited, and a save audits names only. A starting text (with a generated `APP_KEY`) is made for you.
- **An image for production.** nginx and php-fpm in one container on the official PHP image, with the extensions your `composer.json` asks for. Laravel sees HTTPS and the real visitor address without a trusted-proxy change in your code; only `index.php` is executed (an uploaded `.php` file answers 404); the `storage` folders are created on start; logs go to the Logs tab. New Laravel apps get `client_max_body_size 100m;` on their Nginx tab. PHP-FPM and nginx settings can be changed with variables. Assets are built with PHP available when the build needs it (Wayfinder), and `pnpm-workspace.yaml`, `.npmrc` and the other package manager settings files are respected.
- **Deploy without cache.** The arrow next to **Deploy** offers a build that ignores the cache and fetches the base images again, for every kind of app, to pick up base image updates.
- **Wildcard domains and certificates.** Add `*.example.com` to an app and it answers to every name one level below the domain (the bare domain is added on its own; a wildcard takes no `www` redirect). A wildcard name is proven through DNS instead of HTTP. Two ways:
    - **Cloudflare, automatic.** Under Domains > HTTPS > Wildcard certificates paste a Cloudflare API token (from the template _Edit zone DNS_, limited to your zones) and one of your domains. The token is tested, stored encrypted and never shown again; the host agent adds the `_acme-challenge` TXT record itself and removes it, and renewals need nothing from you. Saving and removing the token ask for your password and are audited as high-risk.
    - **By hand, any DNS provider.** The app's Domains tab shows the TXT record to create (with copy buttons) and finishes the certificate as soon as it sees it. **Every renewal asks for a new record** (about every 60 days, with an alert if you use notifications); the certificate in use keeps working meanwhile. **Get new records** starts the order over.

    A wildcard behind Cloudflare's proxy is accepted. Plain names on the same app are still proven over HTTP, all on one certificate. The guide is in the documentation under _Domains and HTTPS_.

- **Metrics for Prometheus and Grafana.** The panel now publishes how busy the server and its containers are at `/api/metrics`, in the format a Prometheus reads: CPU, memory, disk and network of the server and of every container, whether each app and database server is up, and when each app's HTTPS certificate ends. Make a token with the new **Read server metrics** ability (`metrics:read`, needs the **View the server** permission) under Settings > API tokens, and point a Prometheus, on this server or any other, at it. A token limited to some apps sees only those apps. Only numbers and names are published: no variables, logs, addresses or secrets. The panel and the host agent keep working the same way, and nothing new runs on your server. The guide, with a ready scrape configuration, is in the documentation under _Metrics for Prometheus and Grafana_.
- **Four more ready-made apps** (Apps > New app > A ready-made app):
    - **Vaultwarden**, a password manager that works with the Bitwarden apps and browser extensions.
    - **Forgejo**, a small Git host with issues and pull requests (HTTPS only; no SSH port is published).
    - **Umami**, privacy-friendly web analytics. It keeps its data in one of your **PostgreSQL** databases: you choose the database when you install it and CommyPanel links it. Umami ships with the admin password `umami`; CommyPanel replaces it with a generated one on the first start and never touches a password you have set since.
    - **ntfy**, a push notification server. Access is "deny all" by default and an `admin` user with a generated password is made for you; linked apps get `<PREFIX>_USER` and `<PREFIX>_PASSWORD`.

    Vaultwarden, Forgejo and ntfy keep their data in files in a volume, so a deploy stops the old version first (see _Redis, Garage and the apps that keep their data in files_ in the documentation). Vaultwarden and Forgejo have no generated password: make your own account right after the app runs, then switch sign-ups off with the variable named in the app's warning.

The guides are in the documentation under _Laravel apps_, _Domains and HTTPS_ and _Metrics for Prometheus and Grafana_.

## Before you upgrade

- New tables and columns (`app_processes`, `certificates.dns_pending`, and columns on apps, deployments, database servers and database links) are added by the upgrade. No new permissions and no new ports. Run `sudo commypanel upgrade`, which also updates the host agent; this release needs the new agent (containers with a command, the administrator database user for a dedicated server).
- The host agent now contacts `api.cloudflare.com`, and only while a Cloudflare token is connected and a wildcard certificate is being made or the token is being tested. Nothing changes for installs that do not connect one.
- New audit entries: `dns.cloudflare_saved` (high-risk), `dns.cloudflare_removed`, `tls.dns_needed`, `tls.dns_refreshed`, `app.processes_changed` and `app.database_chosen`; `app.env_revealed` and `app.env_changed` now also cover the `.env` editor.
- Editing services needs `apps.update`; choosing a database needs `apps.links`, and `databases.manage` for a new database or server.
- The new ability is `metrics:read`. The API's own contract (`/api/v1`) is unchanged, but its list of token abilities now has one more entry, so an older client library that checks that list strictly may not know `metrics:read` if you use one token for both a Prometheus and the library. Use separate tokens.
- Installing Umami needs the permission to link apps to databases, and the link is recorded in the audit log like any other.

## Known limitations

- Laravel Reverb (it needs a public websocket port), Laravel Octane and private Composer packages (`auth.json`) are not supported yet.
- Laravel images are large (around 800 to 900 MB), and a dedicated database server's own databases are not listed under Databases or part of the panel's backups.
- Inertia SSR runs in its own container; set `INERTIA_SSR_URL` to its address.
- `commypanel:monitor` does not raise an alert when a service container (not the web one) stops.
- Only Cloudflare is connected automatically. Every other DNS provider uses the manual way, where each renewal needs a new TXT record from you.
- A wildcard certificate covers names one level below the domain only (`*.example.com` is not valid for `a.b.example.com` or for `example.com`).
- Metrics are the readings the Usage tab shows: CPU and network are rates over the last few seconds, not counters, and database internals (queries per second, connections) are not included.
- Forgejo works over HTTPS only. Git over SSH needs a published port, which CommyPanel does not offer for apps.
- Vaultwarden's vault in the browser needs HTTPS, so give the app a domain and wait for its certificate.
- Everything in 0.10.1 is unchanged.

## Requirements

Unchanged: Ubuntu 24.04 or 26.04, or Debian 13 or newer, with systemd; `amd64` or `arm64`; root access; at least 1 GB of RAM.

```bash
# Install
curl -fsSL https://github.com/commypanel/panel/releases/latest/download/install.sh | sudo bash

# Upgrade
sudo commypanel upgrade
```
