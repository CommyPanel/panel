# CommyPanel 0.10.0

This release grows the **API** and gives it **clients**: the `commy` command and libraries for Go, Node.js, Python, PHP and .NET. It adds a **deploy mode that stops the old version first** (for software that cannot run twice on the same data), a **Python stack**, and a hardening pass over everything that answers without a login. Please read **Before you upgrade**.

CommyPanel is still pre-1.0.

## What's new

### A bigger API, with a description file

- **New calls** (all under `/api/v1`, each behind its own token ability): start, stop and restart an app (`apps:control`), read its logs (`apps:logs`), list its environment variable **names** and set or remove a variable (`apps:env`), apply changed variables without a build (`apps:deploy`), list an app's deployments (`apps:read`), and `GET /token`, which says what the calling token is and may do.
- **Variables are write-only.** The API never returns a value, and a token needs `apps:env` (and its owner `env.manage`) to touch them. Logs have their own ability because they often hold secrets, and every log read is audited.
- **Every error has an `error` sentence**, a missing record is a plain `Not Found`, and the token page lists the new abilities (each only for people who hold the matching permission).
- **`docs/openapi.yaml`** describes the whole API. Tests keep it equal to the real routes and to what the API answers, and every client is checked against a copy of it.
- **What the API will never do:** open a terminal, read or download volume files, show the credentials of ready-made apps or database passwords, manage users, roles, tokens, settings, backups or certificates, or return a variable's value.
- Audit entries made by a token carry the token's **name** (`via_token`), never the secret.

### Clients

- **`commy`**, a command-line client for your own machine or CI: `commy deploy shop` waits for the result and uses exit codes (`3` for a failed deployment), plus `apply`, `start`, `stop`, `restart`, `logs`, `env set` (the value comes from stdin, never the command line) and more. See _The commy command_ in the docs.
- **Libraries** for **Go**, **Node.js/TypeScript**, **Python**, **PHP** and **.NET** (on `go get`, npm, PyPI, Packagist and NuGet), each in its own repository, with no runtime dependencies, https only, redirects never followed, the token kept out of errors and logs, and bounded retries.
- **`deploy-action`**, a GitHub Action that runs `commy deploy` on a push, waits for the result and fails the job if the deployment fails. It checks the `commy` download against checksums kept in its own repository, refuses pull-request runs, and keeps text from the panel from issuing workflow commands.
- They are separate from the panel: install them from their repositories, and they say which API they speak (`v1`).

### Deploy mode: stop the old version first

- Some software must never run twice on the same data (Redis, Elasticsearch, Garage, many databases). The new **Deploy mode** setting on an app (and in the new-app wizard) can be **Stop the old version first**: the image is built and the release command runs while the old version still serves, then the old version stops, the new one starts and must pass its health check. If it fails, **the old version is started again**, also when the worker dies in the middle.
- The app is **unavailable** between the stop and the moment the new version answers, so use it only where you must. Gradual rollouts and the watch do not apply in this mode, and each deployment's page shows the mode it used. The mode is in the API too.
- **Ready-made Redis, Garage and Elasticsearch apps use it from the start**, and the upgrade moves the ones you already have. The "stop the app first, then deploy" workaround is gone.

### Python apps

- A repository with a `requirements.txt`, `pyproject.toml` or `Pipfile` is detected and built (after .NET, Go and Node, and a repository Dockerfile always wins). The start command comes from a `Procfile` `web:` line, or from the framework: Django and Flask with gunicorn, FastAPI, Starlette and Quart with uvicorn. If it cannot tell, it asks for a `Procfile` line or a Dockerfile.
- Dependencies come from uv, Poetry, `requirements.txt`, Pipenv or a plain `pyproject.toml`; the version from `.python-version`, `runtime.txt` or `requires-python` (3.9 to 3.14, default 3.12). The build runs in the full Python image, and the runtime is the slim image as a non-root user.

### Hardening

- **The list of routes that answer without a login is now short, fixed and tested:** the sign-in and two-factor pages, the one-time setup link, `/up`, two signed webhooks, and the home redirect. Two framework routes the panel never used (Sanctum's cookie route and Laravel's `/storage/{path}`) are switched off.
- **An app can hold at most 200 variables and 256 KB of values** (forms, the wizard and the API), so a loop cannot make an app that no longer starts.
- Log output that is not valid text no longer breaks the logs page or call, and a wrong address under `/api` gets a plain JSON 404 or 405 without a session.

### Also in this release (from 0.9.3 and 0.9.4)

- **The panel's own domain can no longer be lost by accident.** **Use another domain** used to remove the current domain, certificate and site at once. A new name is now only a candidate: the current domain keeps serving until the new one has verified DNS and its own certificate, and switching asks for your password. **Remove domain** is a separate, confirmed action.
- **Servers without IPv6.** nginx only gets IPv6 listeners when the kernel supports IPv6, so it still starts where IPv6 is switched off.
- **New-app wizard:** a domain typed but not added is flagged, and deploying asks what you want.
- **Environment variables:** a pen next to each variable edits just that one after a password confirmation, **Download as .env file** (named `.env.<app>`, password and audited as dangerous) and **Delete all**.
- **Confirmation dialogs on the deployment page** (end the watch, go live again, rollout promote and stop) close at once, and dialog buttons wrap on narrow screens.

### Small fixes

- **Memory on the create page for ready-made apps** (also in 0.9.2): the field is filled with the amount the app is made for, and Elasticsearch, Kibana and n8n refuse less than they need to run.
- **Plain text fields no longer invite autofill.** A browser could put its saved email address into the app name field, and the app's short name (and so its container and image names) then held that address. The fields for signing in and for accounts keep the browser's behaviour.

## Before you upgrade

- **The upgrade adds columns** (`deploy_strategy` on apps and deployments) and moves existing **Redis, Garage and Elasticsearch** ready-made apps to the stop-first mode. Run `sudo commypanel upgrade`.
- **No new permissions and no new ports.** The new token abilities map to permissions that already exist (`apps.control`, `apps.logs`, `env.manage`); your existing tokens keep working and keep only what they had.
- **A stop-first app has a short outage on every deploy**, apply and rollback. Nginx answers 502 until the new version answers.
- Audit entries of API deployments now name the token in `via_token` (before, in `token_name`).

## Security notes

- Tokens are checked against the abilities of the call and against what the owner may do now, on every call. A test walks every API route, also future ones, and fails if one is not behind a token, an ability and a permission.
- The clients refuse plain http (except for localhost, when asked), never follow a redirect, and scrub the token even from what a misbehaving server says. A saved `commy` login is only ever sent to the address it was saved with.

## Known limitations

- Elasticsearch uses the stop-first mode only as a default (change it on the app's Settings tab if it does not suit you). Stop-first has been run on a real server and works.
- A Python dependency that needs a system library at run time (for example `libpq` for `psycopg2`) needs `psycopg2-binary` or your own Dockerfile.
- The Action runs on Linux and macOS runners only (its own tests run on Linux).

## Requirements

Unchanged: Ubuntu 24.04 or 26.04, or Debian 13 or newer, with systemd; `amd64` or `arm64`; root access; at least 1 GB of RAM (2 GB more for Elasticsearch).

```bash
# Install
curl -fsSL https://github.com/commypanel/panel/releases/latest/download/install.sh | sudo bash

# Upgrade
sudo commypanel upgrade
```
