# CommyPanel 0.8.2

A small release with two changes for apps that take a long time to build or start, such as big .NET apps.

## What's new

- **Health check timeout per app.** The app's **Settings** tab, and the **Settings** step of the new-app wizard, now have a **Health check timeout (seconds)** field: how long a new version gets to answer its health check before the deployment fails (10 to 1800). Empty keeps the server default of 60 seconds (`DEPLOY_HEALTH_TIMEOUT`). The failure message names the number that was used.

## Fixes

- **A long build was marked "interrupted" while it was still running.** The queue handed a job that had run for more than 90 seconds to a second worker, which marked the deployment as failed ("The deployment was interrupted", and sent a failure alert) while the first worker kept going and later showed the health check. The queue now waits long enough for the longest deployment (about an hour) before it does that.

## Before you upgrade

- The upgrade adds one column to the apps table. Run `sudo commypanel upgrade`.
- No new ports and no new permissions.

## Known limitations

- If the panel's worker is killed in the middle of a deployment, that deployment now shows as running for up to an hour before it is marked failed, instead of about a minute and a half.

## Requirements

Unchanged: Ubuntu 24.04 or 26.04, or Debian 13 or newer, with systemd; `amd64` or `arm64`; root access; at least 1 GB of RAM.

```bash
# Install
curl -fsSL https://github.com/commypanel/panel/releases/latest/download/install.sh | sudo bash

# Upgrade
sudo commypanel upgrade
```
