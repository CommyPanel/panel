# CommyPanel 0.9.3

A fix for **the panel's own domain**, plus a better domain step in the new-app wizard, easier environment variables, and servers without IPv6.

## What was wrong

On the `/welcome` page, **Use another domain** removed the panel's current domain **at once**, together with its certificate and its nginx site. Anyone who opened the page, pressed it, and left without entering a new name was left with a panel that was no longer served on its domain. Entering a new name had the same effect on the certificate while the old site was still running, and the next upgrade then removed the site.

## What's new

- **The panel domain never changes until the new one is ready.** **Use another domain** now starts a *move*: the current domain, its certificate and its site stay exactly as they are. The page shows the DNS records for the new name and checks them by itself; when they are right, **Switch the panel to ...** (it asks for your password) gets the new certificate first, and only when that works does the panel move. If it fails, nothing changed and you can try again or cancel the move. **Remove domain** is a separate button with its own confirmation and password, and says what it does.
- **Domain step of the new-app wizard.** A domain typed into the form but not added now says so under the button ("... is not added yet"), and **Skip and deploy** / **Create and deploy** asks what you want when something is typed: add it and deploy, deploy without it, or go back.
- **Environment variables.** **View and edit values** shows the values after a password confirmation (a recent one is enough) and saves changes in one go; opening them is audited. **Delete all** removes every variable of the app after a confirmation.
- **Servers without IPv6.** nginx is only given IPv6 listeners when the kernel supports IPv6 (a server with no public IPv6 address is fine, the stack just has to exist). On a server where IPv6 is switched off the installer and the agent leave them out, so nginx still starts. DNS checks already worked with only an A record.

## Before you upgrade

- **No new columns, no new permissions, no new ports.** Run `sudo commypanel upgrade`.
- The installer and the agent change (nginx listeners), so the upgrade rewrites the panel's nginx files once.

## Known limitations

- Moving the panel replaces the certificate files of the panel site just before nginx is rewritten for the new name; if nginx cannot be reloaded at that moment, run `sudo commypanel upgrade` again, which rewrites the panel site.
- Everything else in 0.9.2 is unchanged.

## Requirements

Unchanged: Ubuntu 24.04 or 26.04, or Debian 13 or newer, with systemd; `amd64` or `arm64`; root access; at least 1 GB of RAM.

```bash
# Install
curl -fsSL https://github.com/commypanel/panel/releases/latest/download/install.sh | sudo bash

# Upgrade
sudo commypanel upgrade
```
